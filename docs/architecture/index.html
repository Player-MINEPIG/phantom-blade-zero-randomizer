从启动器进入独立战役

  1. 退出游戏。如果曾安装静态 r1 或 r2，将旧包的同名 .pak、.utoc 和 .ucas 一起移出游戏安装目录的 Paks。
  2. 将发行包解压到游戏安装目录以外。 PBZ-Randomizer.zip
  3. 打开 PBZRandomizer.exe，选择种子，创建独立战役并启动，再在游戏中选新游戏。
  4. 此后用启动器选同一战役，并沿用同一个游戏槽位。游戏从该战役的独立档库读取进度。
  5. 要继续个人原版档，先退出游戏，再从 Steam 正常启动。 安装与兼容说明

浏览器演示 · 换模式后，剩下的奖励去哪了

在启动器选择「切换此战役模式…」，确认当前槽已经领过哪些奖励。游戏退出后，离线编译器按这份记录重写剩余奖励、光效和其他模块，再让启动器为同一份存档选用新布局。已有原版进度可先导入为独立战役副本。下面的三个虚构点位可以试出提前拾取对关闭随机的影响。 游玩说明

每份奖励只发一次。关闭随机时，剩余点位尽量恢复原奖励。如果原奖励已在其他点位发出，仍会在剩余点位补齐未发放的那份奖励。

这次切换在磁盘上改变了什么？

permutation.json 记录每个点位从哪一条原版奖励行取货。两行即使有同名材料，也能分别保留各自的数量。ledger.json 保存点位和领取时的模式；重放这些记录便能算出还有哪些原始奖励未发。

离线编译器从 kit.zip 重建掉落表、需要转发的 Boss 奖励节点、地图光效和所选模块，再用 retoc 打包装回读。所有块核对成功后，启动器一次更新 campaign.json 的布局引用。

下一次启动使用新的 -UserDir 挂载布局，-SaveGamesDir 仍指向这个战役的同一个档库。正常从 Steam 启动时不带这两个参数。

通行资格与武装奖励

当前静态包保留关键通行武装的原版发放点和机关条件。下图展示独立解锁的设计目标。

  1. 通行能力原 Boss 遭遇击败该遭遇的当前对手能力解锁，开放对应障碍
  2. 物品奖励影之武装本体按白名单与池规则重排从分配到的奖励点领取

设计目标是由原 Boss 遭遇的胜利条件授予通行能力。替换该遭遇的对手后，胜利仍能解锁，并且无需取得或装备对应影之武装。

生成器能检查配置中已登记的前置条件。游戏的完整流程依赖图仍待核对。

ModCraft 的适用范围

ModCraft 展示了对话式编辑、项目文件对比、构建和社区发布，也提供支持 Unreal UE4SS 与 Pak 的桌面管理器。公开演示可用于了解创作和部署流程。《影之刃零》的种子复现、可达性检查及专用 IoStore 写入需要项目级测试；本项目已用本地 Python 流程构建 Steam 原生覆盖包。 ModCraft 编辑器说明

《随机增援 MOD》是游戏内动态生成的参考案例。它使用游戏专用 UE4SS，在玩家附近定时新增敌人，或为原有敌人加增援，并保存新生成单位的状态。作者说明可开启额外材料掉落。现有项目通过种子预先重排原版刷怪点和奖励点，实际范围由本机资产映射决定。 随机增援作者说明
